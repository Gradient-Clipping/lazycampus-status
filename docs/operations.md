# 单机运行与故障处理

当前状态页与业务共用一台 K3s 主机，复用采集器和 MySQL，不新增其他机器或监控服务。整机、磁盘和网络入口故障可能同时影响状态页；同机备份不具备异机容灾能力。

## 检查与处置

管理页显示最近采集、采集耗时、邮件任务、存储状态及异常投递计数。`GET /api/v1/admin/metrics` 提供 Prometheus 文本指标，未来可选接入外部监控。采集落后 100 秒、邮件任务停止、存储异常或投递超时应排查。每轮并发上限为 4，相同应用报告只请求一次。

组件定义按解析后的 JSON 比较，仅在新增、变化或重新发现归档组件时批量写入；管理员覆盖和来源归属不被覆盖。监测结果保留每次采样，在所有对应探测完成后按最多 25 个组件一批提交，网络请求不占用数据库事务。组件行按固定顺序加锁，单批失败整体回滚；实际发现时间随观察状态更新，缺失组件不会被错误刷新。对比优化效果时使用相同时间窗口的 MySQL COMMIT 与组件定义写入增量，保持事务持久性设置。

1. 先确认受影响项目，再展开组件的原始结果与时间，区分入口失败、报告过期、业务错误和任务逾期。
2. 在应用日志定位原因；公开 API 不展示学号、邮箱、请求内容、任务名或内部地址。
3. 必要时发布人工事件，说明用户影响与处理进展。Keycloak 不可用时，可使用预先保管的最小权限 API 凭据，仍保留管理审计。
4. 修复后等待恢复阈值通过，不用无数据作为恢复证据。

## 事件与投递

`POST /api/v1/admin/incidents` 支持 `Idempotency-Key`（8–128 个字母、数字、点、下划线、冒号或连字符）。同一身份、键和原请求体重复提交返回同一事件，不重复通知；同键不同内容返回 409。键保留 7 天，重试须复用原请求体和键。

相同项目内的异常合并为一条事件，保留完整受影响组件集合。Sender 明确失败按既有退避重试；`uncertain` 表示结果不确定，须核对投递平台，不能自动重发。

## 备份与演练

既有每日 MySQL 全库备份包含 `lazycampus_status`，新增表沿用同一备份。恢复演练使用独立临时数据库，核对组件、事件、订阅及审计，不覆盖生产数据库。

自动测试使用临时 MySQL 和模拟邮件，覆盖存储中断、锁互斥、幂等事件、合并异常、恢复阈值和订阅边界；适配器测试检查缺表、存储桶缺失、数据过期与业务错误率。生产验收只做读取，不伪造故障或发送测试通知。
